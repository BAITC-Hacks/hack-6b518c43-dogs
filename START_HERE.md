# LEVRA — пакет для старта в Codex

**Это подготовленный стартовый пакет, не готовое конкурсное решение.**
В `agent.py` сейчас скопирован неизменённый шаблон организаторов.

1. Распаковать пакет и перенести его СОДЕРЖИМОЕ в официальный репозиторий команды.
   Не делать новый отдельный репозиторий. Если работа уже начата, не перезаписывать её:
   сравнить файлы и аккуратно добавить материалы. Существующие AGENTS.md/requirements.txt объединить.
2. Открыть этот репозиторий в Codex. Передать текст `docs/PROMPT_01_BUILD.md` либо попросить
   выполнить содержащуюся в нём задачу. CSV не нужно вставлять в чат: они доступны как файлы проекта.
3. После первого этапа получить от Codex фактические результаты и проверить их до расширения UI.

## Стартовые команды (из корня репозитория)

```sh
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python tools/verify_originals.py
python tools/audit_data.py
python local_eval.py
```

На этом исходном шаблоне `FAIL` ожидаем: net у него отрицательный. Команда запуска работает,
но это не законченный агент LEVRA и не прохождение обязательных условий экспертизы.
`requirements.txt` фиксирует зависимости, на которых реально выполнен аудит в этой среде.
При изменении стека Codex должен обновить зависимости и проверить их на вашем компьютере.

## Содержание
- Оригинальные CSV, guide, environment/scorer/eval/submission scripts — без изменений.
- docs/BUILD_BRIEF.md — подробный проект решения.
- docs/PROMPT_01_BUILD.md — первый рабочий промпт.
- docs/DATA_AUDIT.md и reports/ — подтверждённые наблюдения и baseline.
- AGENTS.md — границы и правила реализации.
- STATE.md — текущее честное состояние.
- tools/ — воспроизводимый аудит и проверка оригиналов, не конкурсный алгоритм.

Числа в reports относятся к синтетическому пакету, не к реальному бизнесу Beeline.
Скрытые эффекты недоступны; победа или баллы не прогнозировались.
