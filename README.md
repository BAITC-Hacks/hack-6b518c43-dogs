# BeeAgent

AI-агент для управления маркетинговыми кампаниями. **powered by Beeline**.

Разработано командой для кейса Beeline на HackAlem AI. Используются синтетические данные кейса. Результаты не отражают показатели Beeline. Логотип сохранён с [официального сайта Beeline](https://beeline.kz/ru); источник и локальный файл описаны в [BRAND_SOURCES.md](docs/BRAND_SOURCES.md).

Численное ядро `Agent.act(env)` работает детерминированно без интернета. React + TypeScript, ручное изменение условий, паспорта решений, исправление плана и серверный AI-ассистент используют один `Engine` в `agent.py`. Отдельного демонстрационного движка нет.

## Запуск

Python 3.11+ и Node 20.19+. Один раз установить зависимости:

```sh
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt -r requirements-server.txt
npm --prefix frontend ci
```

Затем одна команда:

```sh
./run.sh
```

Открыть [BeeAgent](http://127.0.0.1:8765). Сервер собирает отсутствующий или устаревший интерфейс и слушает только loopback. Другой порт: `./run.sh --port 8766`. После установки приложение работает без интернета; AI требует отдельного подключения.

Чистое хранилище начинает с пустого списка. «Рассчитать план» объясняет расход ресурсов проверок и запускает официальный локальный расчёт. Сохранённые запуски и версии находятся в `reports/runs/`, не включаются в Git. Для изолированной проверки можно задать `BEEAGENT_STORAGE_DIR` с другим локальным каталогом.

## Подключение AI

Создать `.env` по `.env.example` и **локально** задать новый `OPENAI_API_KEY`. Не вставлять ключ в интерфейс или переписку. Перезапустить сервер. Уже заданные переменные окружения имеют приоритет над `.env`. По умолчанию модель `gpt-6-sol`, предел оценки расходов $5 и 100 вызовов на приложение. Подробности, цены и ограничения: [AI_ASSISTANT.md](docs/AI_ASSISTANT.md).

Ассистент вызывается только по кнопке. Он получает показатели выбранной версии, вызывает настоящий пересчёт и предлагает вариант. Применение выполняет пользователь после сравнения. Без ключа доступны все ручные функции. Успешный внешний вызов OpenAI ещё не проверен; тесты протокола используют подменный SDK с настоящим движком.

## Рабочее место

- **Обзор:** показатели активной версии и отдельное измерение на данных кейса. Для изменённого плана указано «Нет измерения».
- **Кампании:** порядок выполнения, фактический доступный охват, предельный вклад и паспорт. Под таблицей отдельно указан оценочный вклад проведённых проверок.
- **Изменить условия:** общий бюджет, доступные будущие каналы и число кампаний. Наблюдения и уже потраченные ресурсы сохраняются; новых проверок нет. Вариант не применяется автоматически.
- **Сравнение:** базовый и предложенный планы, ограничения и показатели. Также сохранены фактические сравнения способов выбора первого этапа.
- **Проверки:** ошибки правил, пересечения, усечение, неопределённый знак. Расширенный редактор принимает JSON; исправление заново выбирает допустимый план тем же движком. Предупреждения могут остаться.
- **Данные:** источники, ограничения истории и журнал проведённых проверок.

Дизайн обновлён в чёрно-жёлтой айдентике, без Impeccable по указанию пользователя. Все ресурсы локальные, без CDN. Рекламная платформа, пятый канал и интеграция Gradius не добавлялись.

## Как работает агент

История задаёт слабые оценки направлений по текущему тарифу и сегменту выручки. Дубликаты удаляются только в рабочей копии. Отношение выручки после перехода к выручке до него ограничивается; малые группы объединяются с более широкими. Это ассоциация, не причинный эффект и не измеренная конверсия.

Пилоты адаптивно проверяют направления предварительного плана, периодически исследуют другие варианты и обновляют среднее и дисперсию с весом фактического числа контактов. Параметры модели сохранены с первого этапа: минимальная историческая стандартная ошибка 0.24, шум наблюдения 0.804 / sqrt(n), штраф выбора 0.7 стандартной ошибки. Звонки оцениваются отдельно из-за насыщения конверсии. Размеры проверок 40, 100 и 180 выбираются с учётом доступной аудитории, стоимости и ценности информации.

Последовательный выбор с локальными заменами учитывает бюджет, лимит контактов, отсечение кампании до 5000, порядок идентификаторов, повторные расходы и максимум эффекта на клиента, включая отрицательные значения. Состав пилотных выборок неизвестен: их пересечения оцениваются вероятностно, пересечения финальных кампаний считаются точно. Глобальный оптимум не гарантируется. Новый `act` сбрасывает знания; результатов оценщика в агенте нет.

## Фактические результаты

Проверка на данных кейса, прогон 42: **2 434 331.80 у.е.** чистого прироста, расход **99 994**, **15 000** контактов, **11 603** уникальных клиентов, **20** проверок и **8** финальных кампаний.

Прогноз этого плана: **6 432 029.39**, ошибка **+3 997 697.60** (+164.22% от измеренного результата). На десяти отложенных прогонах 10–19 средняя ошибка прогноза **+4 541 357.02**. Расходы и количество контактов совпали с оценщиком. Ошибка эффекта не исправлена коэффициентом или подстановкой измеренного результата: показана явно, интервал модели не выдаётся за откалиброванную гарантию.

|---|---:|---:|---:|
| Прогоны 0–9 | 2 661 673 | 304 998 | 10/10 |

На данных первого этапа адаптивная политика уступает вариантам на истории и с фиксированными проверками. Скрытое судейство неизвестно. Полная диагностика, включая отрицательные исходы: [NUMERICAL_REVIEW.md](docs/NUMERICAL_REVIEW.md), [forecast_audit.json](reports/stage2/forecast_audit.json).

Во втором этапе политика не менялась; в `agent.py` обновлены только имя в описании и названия кампаний. Старые артефакты первого этапа сохранены в `reports/levra/`, исходный шаблон измеряют `reports/baseline_*`. Снимки и проверки до второго этапа: `reports/stage2/before/`.

```sh
source .venv/bin/activate

python -m unittest discover -s tests -v

```

Для самого сдаваемого агента нужны только зависимости `requirements.txt`, без UI и серверного SDK. Формат submission сохранён. Два свежих процесса с разными PYTHONHASHSEED, без ключа и с фиктивным ключом дали одинаковые байты:
`9e6b58079f5abf7b3fa83afe05d6c1b057bf8b3a17981455aedc486cc39a2d77`.

Изменились только имена кампаний; тарифы, фильтры, каналы и порядок совпадают с submission первого этапа. Все 16 защищённых оригиналов неизменны. Проверки и скриншоты: [TESTING_STAGE2.md](docs/TESTING_STAGE2.md). Короткий сценарий показа: [DEMO.md](docs/DEMO.md).

## Оставшиеся ограничения

Прогноз эффекта систематически завышен; калибровка и устойчивость к смене лучшего направления не решены. Пилотная политика может тратить ресурсы на слабые направления. Интервалы не покрывают все ошибки переноса между аудиториями. Внешняя OpenAI-интеграция, её качество и доступ к модели требуют нового локального ключа. Нет реальных рассылок, публичного хостинга, пользовательской авторизации и гарантии результата скрытого судейства.

Папка reports/levra сохраняет сравнения и авторские проверки первого этапа. Файлы latest_snapshot.json, reproducibility.json и api_smoke.json в ней обновляются текущими командами; их исходные версии из первого коммита второго этапа сохранены в reports/stage2/before/.
