# BeeAgent

AI-агент для управления маркетинговыми кампаниями. **powered by Beeline**.

Рабочее решение кейса Beeline на HackAlem AI: детерминированный `Agent.act(env)`, адаптивные пилоты, последовательный выбор кампаний и интерфейс на том же `Engine`. Все данные синтетические; результаты не отражают бизнес Beeline. [Источник официального логотипа](docs/BRAND_SOURCES.md).

## Запуск и сдача

Python 3.11+ и Node 20.19+. Проверена чистая установка на Python 3.12/macOS с пустыми кешами, без API-ключа и пользовательского хранилища.

```sh
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt -r requirements-server.txt
npm --prefix frontend ci
./run.sh
```

Открыть [BeeAgent](http://127.0.0.1:8765). `run.sh` собирает отсутствующий/устаревший интерфейс. Сервер слушает только loopback; другой порт задаётся `--port 8766`. На чистой установке нажать «Рассчитать план»: запуск включает настоящие пилоты и официальный локальный оценщик. После установки ядро и ручные функции работают без интернета.

Для конкурсного агента нужны только `agent.py`, исходный комплект данных и `requirements.txt`. Сервер, OpenAI SDK и Node для `local_eval.py` не требуются. Исходные данные, среда и оценщик не изменены; проверяются хеши 16 файлов.

## Численная политика этапа 3

Исторические переходы задают слабые некаузальные гипотезы с неопределённостью. Пилоты обновляют среднее и дисперсию по фактическому числу контактов. SMS, Push и реклама разделяют переносимую оценку; звонки оцениваются отдельно из-за насыщения. Solver учитывает бюджет, контакты, ограничение кампании 5000 клиентами, порядок выполнения, повторные расходы и максимум эффекта на клиента, включая отрицательные значения. Пилотные пересечения оцениваются вероятностно: ID пилотных клиентов недоступны.

Новая политика `beeagent-repeat-3` повторно проверяет крупные решения после одного наблюдения, если их преимущество перед альтернативой ещё недостаточно определено. С пятого шага приоритет получают до шести таких проверок. Исследование ограничено 20% бюджета и 20% контактов. Исторические дисперсии, шум 0.804/sqrt(n), штраф выбора 0.7 стандартной ошибки и формулы эффекта не подгонялись под оценщик. Глобальный оптимум и калиброванный интервал риска не заявляются.

База этапа 2 сохранена, две гипотезы и критерии отбора зафиксированы до экспериментов. 68 разработочных и 120 отложенных исходов сохранены, включая отрицательные. ## Рабочий интерфейс

- Для точной измеренной версии главный показатель — результат проверки на демонстрационных данных кейса; прогноз и его ошибка показаны отдельно.
- «Как проверки изменили план» использует записанные до/после реальных пилотов планы и оценки. Старым журналам события не дорисовываются.
- Изменение бюджета, каналов и числа кампаний создаёт отдельный вариант на сохранённых наблюдениях. Новых пилотов нет; применение явно подтверждается кнопкой после сравнения.
- Паспорт раскрывает наблюдения, неподтверждённую историю, модельный диапазон и альтернативы. Замечания сгруппированы по допустимости, данным, статистической неопределённости и исполнению.
- Версии сохраняются, переживают перезапуск и экспортируются в отдельный CSV. Экспорт UI не перезаписывает конкурсный `submission.csv`.

Измерение проверяется сервером по run/plan ID, хешу плана, версии и хешу движка, отпечатку использованных данных и снимку наблюдений. Старые несовместимые запуски остаются архивными для просмотра/экспорта; пересчёт новым кодом молча не выполняется. Хранилище `reports/runs/` и SQLite локальные, не коммитятся. Для другого хранилища: `BEEAGENT_STORAGE_DIR`.

## AI для пользователя и проверяющего

**Внешний OpenAI пока не проверен:** нового локального ключа нет. Вызовов и расходов этапа 3 — 0. Ключ из переписки не используется. Подменный SDK в тестах подтверждает протокол, но не качество настоящего выбора инструментов.

Проверяющий подключает собственный ключ, без подписки участника:

```sh
source .venv/bin/activate
python tools/configure_ai.py
# Ввести НОВЫЙ ключ в скрытом приглашении терминала, затем перезапустить сервер:
./run.sh
# Во втором терминале, после расчёта плана:
python tools/check_ai_connection.py
# Только явно разрешённая платная проверка шести формулировок:
python tools/check_ai_connection.py --paid-smoke
```

Настройка создаёт игнорируемый `.env` с правами 0600; существующий файл не перезаписывается. Можно самостоятельно заполнить `.env.example` в `.env` или задать окружение. Ключ не попадает в браузер, Git, логи или отчёты. По умолчанию `gpt-6-sol`, локальный предел оценки расходов **$3**, максимум 100 вызовов; журнал сохраняется между перезапусками. Проверка запрещает дополнительный запас свыше $3 и не сбрасывает расход. Это оценка приложения, не банковский/аккаунтный лимит.

Ассистент вызывается по действию пользователя: получает сводку/паспорт, вызывает настоящий `propose_scenario`, сравнивает версии. Числа и пояснения возвращает сервер по проверенным ссылкам. AI не применяет предложение сам и не запускается при открытии страницы, в unit-тестах или оценщике. [Настройка и ограничения](docs/AI_ASSISTANT.md), [фактический статус](reports/stage3/ai_integration.json).

## Ограничения

Прогноз завышен, перенос истории и смена лучшего направления остаются нерешёнными. Ресурсный лимит и повторные проверки изменялись вместе: их отдельный вклад не измерен. Жёсткого подбюджета исключительно для подтверждений нет, позднему крупному решению может не хватить пилотных ресурсов. Малое число авторских миров не доказывает универсальную устойчивость. Нет проверки скрытого судейства, реальных рассылок, публичного хостинга, многопользовательской безопасности и успешного внешнего AI-запроса.

Исторические отчёты второго этапа сохранены. Файлы `reports/levra/latest_snapshot.json` и `reproducibility.json` обновляются действующими командами; старое имя папки не является текущим брендом. Скрипты `forecast_audit.py` и `forecast_diagnosis.py` относятся к архиву этапа 2; не используйте их для оценки новой политики. Для текущей диагностики есть `tools/diagnose_stage3.py`.
