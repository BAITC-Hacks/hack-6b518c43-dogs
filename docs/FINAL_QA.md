Это явная подготовка prerequisite, а не обход ошибки установки. Linux, Windows и другие версии Python отдельно не проверялись.

Точно выполненный путь:


## Выявленные ограничения

`npm ci` вернул код 0, но сообщил одну уязвимую dev-зависимость высокой серьёзности: Vite 7.1.7. Дополнительный `npm --prefix frontend audit --json` вернул код 1, а `npm --prefix frontend audit --omit=dev --json` вернул код 0 и 0 уязвимостей. [Полный audit](../reports/final/npm_audit.json), [runtime audit](../reports/final/npm_audit_production.json).

Штатный run.sh вызывает Vite только для сборки статических файлов, затем запускает Python-сервер. В частности, [официальное уведомление Vite о WebSocket](https://github.com/vitejs/vite/security/advisories/GHSA-p9ff-h696-f583) описывает уязвимость доступного по сети dev server. Это не заявление о полной безопасности проекта: проблема dev-зависимости остаётся, обновление требует отдельной проверки после freeze. Пакеты перед сдачей не менялись.

Новых платных API-вызовов не было. Исторический статус сохраняется: GPT-5.4 mini, 4/6 первых сценариев полностью прошли; два исправления проверены локально, повтор внешних сценариев не авторизован. Прогноз некалиброван, в авторских стресс-мирах были регрессии. Реальные рассылки, многопользовательская защита, скрытое судейство и полная проверка Safari/Firefox/скринридера не выполнялись.
