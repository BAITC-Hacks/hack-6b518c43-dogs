# Серверный ассистент BeeAgent

Ассистент включается только по кнопке пользователя. `Agent.act(env)`, оценщик, ручной пересчёт и экспорт не зависят от OpenAI. Поддержка реализована через официальный Python SDK `openai==2.54.0`, Responses API, строгие схемы инструментов и структурированного ответа.

Документация проверена 23 сентября 2026:
- [Модель gpt-6-sol](https://developers.openai.com/api/docs/models/gpt-6-sol)
- [Вызов инструментов](https://developers.openai.com/api/docs/guides/function-calling)
- [Структурированный ответ и поддерживаемая часть JSON Schema](https://developers.openai.com/api/docs/guides/structured-outputs)

## Настройка

Скопировать `.env.example` в `.env`, если локальный файл ещё не создан. В `.env` пользователь самостоятельно задаёт новый `OPENAI_API_KEY`, затем перезапускает сервер. Старый ключ из переписки не используется. Файл игнорируется Git. `load_dotenv(..., override=False)` загружает именно серверный файл; уже заданные переменные окружения имеют приоритет.

По умолчанию `OPENAI_MODEL=gpt-6-sol`, защитный предел `BEEAGENT_AI_BUDGET_USD=5`, максимум `BEEAGENT_AI_MAX_CALLS=100`. Лимиты относятся к этому локальному приложению. При смене модели необходимо указать проверенные цены четырьмя переменными из `.env.example`; неизвестная модель без цен не включается.

Стандартные цены gpt-6-sol для короткого контекста, использованные в локальной оценке: вход $2, чтение кеша $0.20, запись кеша $2.50, выход $10 за миллион токенов. Контекст запроса ограничен 60 KB, поэтому длинный контекст не используется. Цена и доступность модели в конкретном API-проекте требуют проверки новым ключом.

## Инструменты и подтверждение

- `get_plan_summary`: агрегаты, ограничения, кампании, степень поддержки наблюдениями и ссылки на показатели.
- `get_campaign_evidence`: паспорт выбранной кампании, её наблюдения проверок, нужные строки тарифов, стоимость контакта и замена канала в целом плане.
- `propose_scenario`: реальный `Engine.solve` на неизменяемом снимке. Процент бюджета считается от лимита выбранной базовой версии. Возвращает отдельную версию, сохраняет потраченные ресурсы, не запускает пилоты.
- `compare_plans`: показатели двух разрешённых версий в одном запуске.

Ни один инструмент не применяет план. После сравнения пользователь нажимает «Применить этот вариант». Сервер проверяет, что активная версия не изменилась в другой вкладке. Повтор запроса с той же базой не уменьшает бюджет повторно. Экспорт получает конкретный `plan_id` и не записывает официальный `submission.csv`.

LLM выбирает `metric_ids` и `evidence_ids`, а сервер проверяет их существование в ответах инструментов. Числа, подписи и формулировки оснований создаёт сервер из движка. Свободное числовое объяснение модели не принимается схемой. Это сознательно ограниченный ассистент решений, а не универсальный чат. Передаются агрегаты, выбранные кампании, результаты соответствующих проверок и тарифы; полные клиентские профили и история не отправляются.

## Ограничения исполнения

Не более трёх обращений к модели на действие, один повтор при временной ошибке, общий таймаут 40 секунд. SDK retries отключены. Один активный запрос, до шести новых действий за минуту, до 2000 символов пользовательского ввода и до 1800 выходных токенов на вызов. Неизвестные инструменты, лишние поля, неверные перечисления и ссылки отклоняются. Возвращаются понятные отказы без исходных исключений провайдера. Обработаны отсутствие ключа, 401, 403, 404, 429, временные сетевые ошибки, отказ модели и неполный ответ.

Токены SDK, модель, длительность и оценка USD хранятся в SQLite в `reports/runs/assistant.sqlite3`. Учтены `input_tokens`, `output_tokens`, `cached_tokens`, `cache_write_tokens`. Перед запросом резервируется консервативная сумма. При неопределённом ответе резерв сохраняется: такой запрос мог быть оплачен. Счётчик переживает перезапуск, включая незавершённые резервы. Это не баланс аккаунта и не точная гарантия биллинга.

Кеш привязан к версии протокола, модели, русскому языку, запросу, выбранной кампании, версии плана, ограничениям и снимку данных. Сохраняется готовый ответ с числовыми ссылками. Ключ, пользовательский текст запроса и сырое исключение в журнал вызовов не записываются.

Сервер слушает `127.0.0.1`, проверяет Host и Origin. Это локальный инструмент без пользовательской авторизации, не публичный платный прокси. Отмена AI-запроса отменяет ожидание SDK и не применяет план. Отмена ожидания исследования не возвращает ресурсы: уже запущенный локальный расчёт завершается на сервере.

## Что проверено

Тесты используют явно подменённый SDK-клиент и настоящий Engine: все четыре инструмента, применение, повтор запроса, кеш, бюджет, ошибки провайдера, таймаут, отмена, попытка неизвестного инструмента, несуществующие ссылки и числовой текст вне схемы. HTTP и браузер проверены без ключа. Платных запросов в этой проверке не было.

**Не проверено:** успешное обращение к внешнему OpenAI, доступ API-проекта к gpt-6-sol, задержка и качество выбора инструментов настоящей моделью. Успех подменного клиента не считается внешней интеграционной проверкой.

## Этап 3: проверка для владельца и проверяющего

Модель и текущие возможности Responses/function calling повторно сверены 23.09.2026 по [официальной странице модели](https://developers.openai.com/api/docs/models/gpt-6-sol) и [function calling](https://developers.openai.com/api/docs/guides/function-calling). Доступ конкретного проекта к модели требует реального запроса; ошибка доступа к модели не равна недоступности всего API.

`python tools/configure_ai.py` запрашивает новый ключ скрытым вводом в локальном терминале, создаёт игнорируемый `.env` с правами 0600 и не перезаписывает существующий. Скрипт не обращается к API. Проверяющий использует собственный ключ; подписка и ключ участника не требуются. После установки зависимостей все ручные функции доступны без ключа и интернета.

`python tools/check_ai_connection.py` проверяет конфигурацию и состояние запущенного локального backend, не делает внешних запросов. `--paid-smoke` явно включает шесть запросов: три требуемых сценария и три переформулировки, отсутствующие в unit-тестах. Используются штатные HTTP/Assistant/PlanService, реальные версии и сохранённые наблюдения. Относительный процент всегда относится к исходной явно выбранной базе. Предложения не применяются автоматически: следующий шаг — сравнение и кнопка в UI. Внешний smoke не заменяет ручную проверку взаимодействия с настоящими ответами в браузере.

Лимит по умолчанию снижен до $3 накопленной локальной оценки; прежняя SQLite не сбрасывается. Smoke отказывается работать, если остаток установленного лимита превышает $3. При существующем расходе можно локально задать общий предел не выше уже учтённой суммы + $3. Неопределённые/отменённые вызовы остаются учтёнными по резерву. Это не гарантия счёта провайдера.

Ответ backend теперь содержит `network_call`, `cached`, задержку и приращение usage (вызовы, стоимость, вход/выход/cache read/cache write). Каждый выполненный инструмент содержит проверенные параметры, разрешённые ограничения, plan ID и снимок данных. Кешированный ответ получает нулевое приращение вызовов и не называется сетевым запросом. Подменный SDK явно отмечается `network_call=false`. Метаданные алгоритма/данных включены в контекст и ключ кеша; архивные несовместимые запуски требуют нового расчёта.

Фактический статус: нового локального ключа нет; внешних вызовов 0, оценка расхода $0, реальные инструменты через OpenAI и реальная задержка модели не проверены. `reports/stage3/ai_integration.json` содержит точный статус. Ключи из переписки не использовались и не сохранялись.
