# LEVRA — Campaign Decision Engine

Рабочий offline-агент для синтетического кейса Beeline / HackAlem и локальное рабочее место аналитика. Численное ядро, what-if, паспорта решений и исправление плана используют один `Engine` в `agent.py`. Реальных рассылок и интеграции с Beeline нет.

## Быстрый запуск

Требуются Python 3.11+ и Node 20.19+ (Node нужен только для сборки UI).

```sh
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
npm --prefix frontend ci
npm --prefix frontend run build
./run.sh
```

Открыть http://127.0.0.1:8765 и нажать **«Исследовать в симуляции»**. Сервер слушает только loopback. После установки и сборки приложение работает без интернета. Повторный запуск — `./run.sh`; другой порт — `./run.sh --port 8766`.

Python scoring path не требует Node, UI, API-ключа или LLM:

```sh
source .venv/bin/activate
python local_eval.py
python local_eval.py --runs 10
python make_submission.py
python tools/verify_originals.py
python -m unittest discover -s tests -v
python tools/check_reproducibility.py
```

Не менять `agent_template.py`, данные и файлы среды/оценщика. Проверка хешей сверяет 16 оригиналов. Сдаваемый `agent.py` самодостаточен относительно наших Python-модулей, но использует выданный `data/change_tariff.csv`, если он доступен. При отсутствии истории остаются широкие priors по справочнику.

## Как принимает решения

1. Клетки `current_tariff × arpu_segment` строятся из публичного профиля. ID используется только для официальной сортировки аудитории. Строки с отсутствующими ключевыми признаками учитываются в диагностике.
2. Исторические полные дубликаты удаляются только из копии. Наблюдения с ARPU до перехода <100 исключаются, before/after ratio ограничивается диапазоном [−1, 2]. Оценки объединяются с более широкими группами; цена и пакеты служат слабым контекстом. Историческая ассоциация не считается causal uplift, а доля направления — измеренной конверсией.
3. Нижний уровень prior SD = 0.24 — наш гиперпараметр сдвига аудитории. По фактическому `n_customers` выполняется Normal–Normal update с шумом `0.804 / sqrt(n)`. При первом наблюдении, расходящемся с prior более чем на 3 прогнозных σ, дисперсия prior увеличивается: это явная эвристика конфликта истории и пилота.
4. Адаптивная разведка пересчитывает предварительный план. Большинство пилотов относится к решениям этого плана, каждый четвёртый шаг открывает всю аудиторию. Крупные неподтверждённые гипотезы получают обязательную проверку. Размер выбирается из 40/100/180 с учётом фактической аудитории, стоимости, контактов и ожидаемого уменьшения неопределённости. Есть бюджет исследования, остановка по ценности информации и лимит пилотов. Это эвристика, не точный VOI.
5. Для каналов с multiplier ≤1 перенос линейный при допущении base conversion ∈ [0,1]. Звонки имеют независимую оценку и не наследуют точность SMS. Ценность эксперимента ограничена реально доступным будущим охватом канала.
6. Детерминированный greedy выбирает предельный вклад в совокупный net со штрафом `0.7 × SD`, затем пробует перестановки и локальные замены. Считаются реальные фильтры, сортировка, cap 5000, остатки, повторные расходы и максимум эффектов клиента, включая отрицательные. Большие клетки можно делить только допустимыми фильтрами; мелкие объединяются по текущим тарифам.
7. ID пилотной выборки неизвестны. Ресурсы и пересечения финальных кампаний точны; пересечения пилотов оцениваются вероятностно по независимой равномерной выборке. Forecast — подстановка средних оценок, не калиброванное распределение net.

Все тарифы и кандидаты выводятся из публичных данных; списков «победителей» нет. Новый `act` полностью сбрасывает знания. `agent.py` не импортирует `mock_environment`, оценщик, результаты бенчмарков или synthetic truth.

## Интерфейс

- **План кампаний:** фактический результат Official mock отделён от Forecast; порядок, охват и предельный вклад каждой кампании.
- **What-if:** бюджет, доступные каналы, максимум кампаний; сравнение с исходным прогнозом. Пилотные расходы сохраняются. Бюджет ниже уже потраченного отклоняется. Новых пилотов — 0; официальный оценщик не патчится.
- **Паспорт:** историческая поддержка, пилоты, posterior и интервалы, снимок знаний, лучшая альтернатива среди замен тарифа и ограничения оценки.
- **Проверка плана:** редактирование JSON; ошибки контракта, пересечения, усечения, неподтверждённые гипотезы и неопределённый знак. Исправление использует тот же solver; показывает проверку до/после. Предупреждения могут остаться, если проблема допустима правилами или данных недостаточно.
- **Исследование и сравнение:** фактический журнал и бенчмарки; live-выполнение обозначено отдельно от replay сохранённого запуска.

`backend/server.py` — тонкий сервер на Python standard library; `frontend/` — React + TypeScript с локальными ресурсами без CDN. Дизайн реализован напрямую по последнему указанию пользователя, без Impeccable. LLM-функции не реализованы и не включаются при наличии ключа.

Артефакты UI сохраняются в `reports/runs/` (локальные, gitignored), сценарии — в `reports/runs/scenarios/`. Чистый clone начинает с пустого списка запусков. Снимок официальной submission-проверки доступен в отслеживаемом `reports/levra/latest_snapshot.json`.

## Ограничения

Solver не гарантирует глобальный оптимум, shortlist и локальные замены могут пропустить лучшие сочетания. Пилотные пересечения вероятностные. Редкие полезные направления и сильный сдвиг истории остаются слабым местом. На очень большой или нетипичной новой базе время <240 с отдельно не подтверждено. Нет LLM-ассистента, авторизации, реальных каналов связи, облачного развёртывания и проверки скрытого судейства.
